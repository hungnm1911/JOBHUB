> **Ngôn ngữ:** Tiếng Việt

## 1. Mục đích

Tài liệu này định nghĩa canonical persistence/data contract để hỗ trợ:

```text
docs/product/versions/v4.1-vietnam-location-migration.md
```

Product Specification là authority đối với business behavior.

V4.1 thay thế persistence representation của Location legacy dạng fixed string literal bằng representation hỗ trợ hierarchy:

```text
Province
└── optional District-level unit
```

Canonical reference source là **Province Open API v1** tại
`https://provinces.open-api.vn/api/v1/`, dùng bộ dữ liệu địa giới trước sáp
nhập tháng 07/2025. Province Open API v2 / bộ dữ liệu post-merger 34 tỉnh và
local hard-coded Location vocabulary không phải canonical source của V4.1.

Data Contract này xác định:

- dữ liệu Location nào cần được persist;
- dữ liệu Location nào không cần tạo collection riêng;
- representation mới của `Job.location`;
- representation mới của `CandidateCV.preferredLocations`;
- relationship giữa Province và District-level unit ở persistence boundary;
- field và local constraint;
- index phục vụ Job Discovery và Candidate Search;
- persistence state hợp lệ;
- persistence transition từ Location legacy sang V4.1;
- constraint nào do schema/database bảo vệ;
- constraint nào cần semantic validation ngoài schema;
- compatibility với các version sử dụng Location trước V4.1;
- persistence nào chủ động không được thêm.

Data Contract này không thay đổi các business rule đã được Product Specification V4.1 xác lập.

Đặc biệt, Data Contract không được dùng để thay đổi:

- một Job có đúng một Location;
- Province là bắt buộc;
- District-level unit là optional;
- Province-only là hợp lệ;
- District-level unit-only là không hợp lệ;
- Candidate có thể có nhiều preferred Locations;
- Job Discovery và Candidate Search có matching semantics khác nhau tại Province/District-level unit boundary;
- `FOREIGN` bị loại bỏ;
- `REMOTE` tiếp tục thuộc WorkMode.

## 2. Thay đổi so với version trước

V4.1 thay representation Location tại các entity đang persist canonical Location.

| Entity / Data | Trạng thái | Mô tả |
|---|---|---|
| `jobs` | `UPDATED` | `location` chuyển từ scalar legacy Location sang structured Province/District-level unit Location |
| `candidate_cvs` | `UPDATED` | `preferredLocations` chuyển từ mảng legacy literal sang mảng structured Location selections |
| Legacy fixed `Location` vocabulary | `REMOVED` khỏi canonical persistence contract | Không còn là authority cho persisted Location mới |
| `categories` | `UNCHANGED` | Không liên quan Location migration |
| `experience_levels` | `UNCHANGED` | Không liên quan Location migration |
| `applications` | `UNCHANGED` | Không persist Location riêng; tiếp tục lấy Location từ Job theo contract hiện hành |
| `job_invitations` | `UNCHANGED` | Không tạo duplicate Location persistence |
| `companies` | `UNCHANGED` | Company address không bị reinterpret thành canonical Location V4.1 |
| `users` | `UNCHANGED` | Không thay đổi |
| `company_members` | `UNCHANGED` | Không thay đổi |

### 2.1. Entity mới

V4.1 **không tạo persisted Location catalog entity mới**.

Không tạo:

```text
locations
provinces
districts
wards
```

thành canonical MongoDB collections chỉ để mirror external Location source.

Province Open API v1 là canonical external reference data source.

Persistence của JOBHUB chỉ lưu identifier Location cần thiết trên business entity sử dụng Location.

### 2.2. Entity được mở rộng / thay representation

```text
jobs
candidate_cvs
```

### 2.3. Entity giữ nguyên nhưng được sử dụng

```text
applications
job_invitations
```

Các entity này không nhận thêm Location field nếu hiện tại chúng chỉ expose Location thông qua Job.

Không duplicate Location vào các entity này chỉ để tiện serialization.

## 3. Collection / Entity tổng thể

Các persisted collection bị ảnh hưởng trực tiếp:

```text
jobs
candidate_cvs
```

Các value object persistence mới:

```text
JobLocation

PreferredLocationSelection
```

Hai value object này là embedded persistence representation.

Chúng không tồn tại độc lập và không có identity riêng.

### Responsibility

| Entity / Value Object | Responsibility |
|---|---|
| `jobs` | Persist đúng một Job Location theo business lifecycle hiện hành |
| `JobLocation` | Persist Province và optional District-level unit của Job |
| `candidate_cvs` | Persist tập preferred Location của Candidate |
| `PreferredLocationSelection` | Persist một Province-wide preference hoặc một exact District-level unit preference |
| Province Open API v1 | Cung cấp canonical pre-merger Province/District-level unit reference data; không phải collection của V4.1 |

Không tạo thêm collection ngoài danh sách trên nếu chưa có canonical requirement mới.

## 4. Quan hệ dữ liệu

### 4.1. External Province → District-level unit

Persistence trong JOBHUB không sở hữu Province/District-level unit entity riêng, nhưng code được persist phải tuân thủ relationship:

```text
Province 1 ───── N District-level unit
```

Một District-level unit code chỉ hợp lệ trong Location nếu District-level unit đó thuộc Province code đi kèm theo canonical external Location source.

Province Open API v1 raw data biểu diễn quan hệ cần dùng trực tiếp bằng:

```text
Province.code
  ← District.province_code
```

Raw `District` chính là District-level unit canonical của JOBHUB và có trực
tiếp `province_code`. Live dataset được kiểm chứng ngày 2026-10-06 có 63
Province và 696 District; Province codes và District codes đều unique trong
từng entity type, và mọi District resolve được đúng một Province. Vì vậy
relationship `Province → District-level unit` là deterministic.

Raw Ward/Commune bên dưới District không được normalize vào canonical Location
V4.1. JOBHUB persist `provinceCode` và optional `districtCode`; không persist
`districtName`, raw Ward data hoặc provider raw payload trên Job/CandidateCV.

Đây là semantic reference relationship, không phải database foreign-key relationship.

### 4.2. Job → JobLocation

**Cardinality**

```text
Job 1 ───── 0..1 JobLocation
```

`0` chỉ được tồn tại khi Job lifecycle hiện hành cho phép Location chưa được hoàn thiện.

Khi Job phải có completed Location:

```text
Job 1 ───── 1 JobLocation
```

**Owner**

```text
Job
```

**Reference**

Không có persisted reference tới Location collection.

`JobLocation` giữ canonical Province/District-level unit codes.

### 4.3. CandidateCV → PreferredLocationSelection

**Cardinality**

```text
CandidateCV 1 ───── 0..N PreferredLocationSelection
```

**Owner**

```text
CandidateCV
```

Mỗi preferred selection biểu diễn một trong hai semantic:

```text
Province-wide preference
```

hoặc:

```text
exact District-level unit preference within Province
```

Nhiều exact District-level unit selections có thể cùng thuộc một Province.

Nếu Candidate chọn toàn Province thì không được đồng thời persist exact District-level unit selections cùng Province đó.

## 5. `jobs`

### 5.1. Responsibility

Collection `jobs` tiếp tục sở hữu canonical Location của Job.

V4.1 thay persistence representation của:

```text
Job.location
```

từ scalar legacy Location thành embedded structured Location.

`jobs` chịu trách nhiệm persist:

- Province của Job;
- optional District-level unit của Job.

`jobs` không chịu trách nhiệm persist:

- toàn bộ external Location catalog;
- danh sách District-level unit của Province;
- Ward/Commune hoặc cấp phường/xã/thị trấn;
- country;
- `FOREIGN`;
- Location alias;
- Location history;
- Location provider raw payload;
- current external Location dataset.

---

### 5.2. Fields

Canonical V4.1 representation:

```text
location {
  provinceCode
  districtCode
}
```

| Field | Type | Required | Default | Constraint | Ý nghĩa |
|---|---|---:|---|---|---|
| `location` | Embedded Document / `null` | conditional | `null` | structured Job Location | Canonical Job Location |
| `location.provinceCode` | `String` | YES nếu `location != null` | — | non-empty canonical Province code | Province của Job |
| `location.districtCode` | `String \| null` | NO | `null` | nếu có phải là District-level unit thuộc `provinceCode` | Optional District-level unit |

Canonical codes được persist dưới dạng `String`.

Province Open API v1 trả Province `code`, District `code` và District
`province_code` dưới dạng JSON integer. Tại persistence boundary, canonical
`provinceCode` và `districtCode` là decimal string tương ứng
(`String(rawCode)`).

Code được coi là opaque identifier.

Không được:

- convert code thành numeric business identifier;
- suy diễn hierarchy từ format của code;
- suy diễn Province từ District-level unit code mà bỏ qua canonical relationship validation.

### 5.3. Enum

`Job.location` không sử dụng enum Province/District-level unit hard-code trong V4.1.

Không tồn tại canonical enum kiểu:

```text
HA_NOI
DA_NANG
...
FOREIGN
```

cho Job Location mới.

### 5.4. Indexes

V4.1 thay Location-related discovery indexes dựa trên scalar legacy Location.

Các query patterns được Product Contract yêu cầu gồm:

1. filter Job theo toàn Province;
2. filter Job theo exact District-level unit;
3. giữ các visibility/deadline conditions hiện hành của Job Discovery.

Canonical index requirements:

| Index | Loại | Mục đích |
|---|---|---|
| `{ status: 1, "location.provinceCode": 1, applicationDeadline: 1 }` | Compound | Job Discovery theo Province |
| `{ status: 1, "location.provinceCode": 1, "location.districtCode": 1, applicationDeadline: 1 }` | Compound | Job Discovery theo exact District-level unit |

Legacy index dựa trên scalar:

```text
{ status, location, applicationDeadline }
```

không còn là canonical V4.1 Location index sau migration.

Không thêm index theo Location name vì Product Specification không định nghĩa search/filter bằng display name.

### 5.5. Embedded documents

#### `JobLocation`

```text
JobLocation {
  provinceCode
  districtCode
}
```

`JobLocation`:

- chỉ tồn tại bên trong Job;
- không có `_id` business riêng;
- không có lifecycle độc lập;
- không có timestamps riêng;
- không có `FOREIGN`;
- không có Ward/Commune hoặc cấp phường/xã/thị trấn;
- không chứa raw external Location object.

`districtCode = null` biểu diễn Province-only Location.

### 5.6. Reference rules

| Field | Reference | Required | Cardinality | Rule |
|---|---|---:|---|---|
| `provinceCode` | External canonical Province | YES nếu Location tồn tại | N → 1 conceptual | Code phải xác định Province hợp lệ |
| `districtCode` | External canonical District-level unit | NO | N → 1 conceptual | Nếu có, District-level unit phải thuộc `provinceCode` |

Đây không phải database reference tới collection nội bộ.

## 6. `candidate_cvs`

### 6.1. Responsibility

`candidate_cvs` tiếp tục sở hữu Candidate preferred Locations.

V4.1 thay:

```text
preferredLocations: String[]
```

bằng structured selections.

Canonical representation:

```text
preferredLocations: [
  {
    provinceCode,
    districtCode
  }
]
```

Một item có:

```text
districtCode = null
```

nghĩa là preference toàn Province.

Một item có:

```text
districtCode != null
```

nghĩa là preference exact District-level unit trong Province đó.

Ví dụ business:

```text
Hà Nội
├── Ba Đình
└── Ba Vì

Hồ Chí Minh
└── ALL
```

có persisted representation tương đương:

```text
[
  { provinceCode: HANOI_CODE, districtCode: BA_DINH_CODE },
  { provinceCode: HANOI_CODE, districtCode: BA_VI_CODE },
  { provinceCode: HCM_CODE, districtCode: null }
]
```

Persistence representation này không làm thay đổi Product semantics.

### 6.2. Fields

| Field | Type | Required | Default | Constraint | Ý nghĩa |
|---|---|---:|---|---|---|
| `preferredLocations` | Array of `PreferredLocationSelection` | NO | existing/default empty behavior | distinct canonical selections | Preferred Locations |
| `preferredLocations[].provinceCode` | `String` | YES | — | non-empty canonical Province code | Province preference |
| `preferredLocations[].districtCode` | `String \| null` | NO | `null` | nếu có phải thuộc Province | Province-wide hoặc exact District-level unit preference |

### Local canonical identity

Một preferred selection có canonical identity:

```text
Province-wide:
PROVINCE:<provinceCode>

Exact District-level unit:
DISTRICT:<provinceCode>:<districtCode>
```

Đây là persistence comparison semantics.

Không yêu cầu persist chuỗi key này thành field riêng.

### Duplicate rules

Không được persist hai exact selections giống nhau:

```text
(P, D)
(P, D)
```

Không được persist nhiều Province-wide selections cùng Province:

```text
(P, null)
(P, null)
```

Không được đồng thời persist:

```text
(P, null)
```

và:

```text
(P, D1)
(P, D2)
```

vì Product Contract xác định một Province preference phải là:

```text
ALL
```

hoặc:

```text
District-level unit subset
```

chứ không đồng thời cả hai.

### 6.3. Enum

Không có enum Location hard-code.

Không persist `ALL` dưới dạng fake District-level unit code.

Semantics:

```text
districtCode = null
```

trong một preferred selection biểu diễn Province-wide preference.

### 6.4. Indexes

Candidate Search yêu cầu hai query semantics:

- Province search match cả Province-wide và District-level unit-specific preferences trong Province;
- District-level unit search match Province-wide preference cùng Province hoặc exact District-level unit preference.

Canonical Location search index:

```text
{
  "preferredLocations.provinceCode": 1,
  "preferredLocations.districtCode": 1,
  updatedAt: -1,
  _id: -1
}
```

Index tiếp tục áp dụng cùng visibility/archive boundary mà Candidate Search hiện hành yêu cầu.

Không tạo:

- index theo Location name;
- geospatial index;
- full-text Location index.

Nếu physical database engine không thể sử dụng compound representation trên cho query pattern thực tế như dự kiến, Engineering/implementation phải đề xuất persistence-equivalent index khác mà không thay đổi Product/Data semantics.

Data Contract không cho phép thay business representation chỉ để phục vụ một index speculative.

### 6.5. Embedded documents

#### `PreferredLocationSelection`

```text
PreferredLocationSelection {
  provinceCode
  districtCode
}
```

Embedded document:

- thuộc CandidateCV;
- không tồn tại độc lập;
- không có business identity ngoài composite Province/District-level unit meaning;
- không có timestamps riêng;
- không persist display name;
- không persist hierarchy khác Province/District-level unit.

### 6.6. Reference rules

| Field | Reference | Required | Cardinality | Rule |
|---|---|---:|---|---|
| `provinceCode` | External canonical Province | YES | N → 1 conceptual | Province phải hợp lệ |
| `districtCode` | External canonical District-level unit | NO | N → 1 conceptual | Nếu có phải thuộc Province tương ứng |

# 7. State Matrix

## 7.1. Job Location persistence

| `location` | `provinceCode` | `districtCode` | Hợp lệ | Ý nghĩa |
|---|---|---|---:|---|
| `null` | — | — | Conditional | Chỉ hợp lệ khi Job lifecycle cho phép chưa có Location |
| object | Có | `null` | YES | Province-only |
| object | Có | Có và thuộc Province | YES | Province + District-level unit |
| object | Không | `null` | NO | Missing Province |
| object | Không | Có | NO | District-level unit-only |
| object | Có | District-level unit thuộc Province khác | NO | Invalid hierarchy |

## 7.2. Candidate preferred Location persistence

Đối với một Province P:

| Persisted selections | Hợp lệ | Ý nghĩa |
|---|---:|---|
| Không có selection P | YES | Candidate không chọn Province P |
| `(P, null)` | YES | Toàn Province P |
| `(P, D1)` | YES | Exact District-level unit |
| `(P, D1), (P, D2)` | YES | District-level unit subset |
| `(P, null), (P, D1)` | NO | ALL và subset cùng lúc |
| `(P, D1), (P, D1)` | NO | Duplicate |
| `(P, D thuộc Province khác)` | NO | Invalid hierarchy |
| `(null, D)` | NO | District-level unit-only |

# 8. Persistence Transitions

## 8.1. Job Location: unset → Province-only

### Trigger business

Product F02.

### Trước

```text
Job.location = null
```

### Sau

```text
Job.location = {
  provinceCode: P,
  districtCode: null
}
```

### Entity bị thay đổi

- `Job`

### Invariant cần giữ

- P là Province hợp lệ;
- Job ownership/lifecycle hiện hành cho phép chỉnh Location.

---

## 8.2. Job Location: Province-only → Province + District-level unit

### Trước

```text
location = {
  provinceCode: P,
  districtCode: null
}
```

### Sau

```text
location = {
  provinceCode: P,
  districtCode: D
}
```

### Invariant cần giữ

```text
D belongs to P
```

---

## 8.3. Job Location: Province + District-level unit → Province-only

### Trước

```text
location = {
  provinceCode: P,
  districtCode: D
}
```

### Sau

```text
location = {
  provinceCode: P,
  districtCode: null
}
```

Không có persisted District-level unit artifact cũ được giữ lại trong Job Location.

---

## 8.4. Job Location: đổi Province

Nếu Job Location đổi từ Province A sang Province B, persisted state sau transition phải là một Location hợp lệ hoàn chỉnh.

Không được tồn tại intermediate persisted state kiểu:

```text
provinceCode = Province B
districtCode = District-level unit thuộc Province A
```

Transition phải làm thay đổi Location như một persistence unit.

---

## 8.5. Candidate thêm Province-wide preference

### Trước

Candidate không có selection của Province P.

### Sau

```text
preferredLocations += {
  provinceCode: P,
  districtCode: null
}
```

Không được đồng thời còn exact District-level unit selections của P.

---

## 8.6. Candidate chuyển Province-wide → District-level unit subset

### Trước

```text
(P, null)
```

### Sau

```text
(P, D1)
(P, D2)
...
```

Trong persisted state hoàn tất không được tồn tại đồng thời:

```text
(P, null)
```

với District-level unit subset của P.

---

## 8.7. Candidate chuyển District-level unit subset → Province-wide

### Trước

```text
(P, D1)
(P, D2)
...
```

### Sau

```text
(P, null)
```

Toàn bộ exact District-level unit selections cùng Province P phải được loại bỏ khỏi persisted state của CV.

---

## 8.8. Candidate thay đổi District-level unit subset

Sau transition:

- chỉ các District-level unit được Candidate chọn còn tồn tại;
- không duplicate selection;
- tất cả District-level unit phải thuộc Province tương ứng.

---

## 8.9. Legacy Job Location migration

### Trước

```text
Job.location = LEGACY_PROVINCE_LITERAL
```

### Sau

```text
Job.location = {
  provinceCode: mappedProvinceCode,
  districtCode: null
}
```

Không tự suy ra District-level unit.

Mỗi legacy Vietnam Location literal cần có deterministic migration mapping tới canonical Province code của approved external Location dataset dùng cho migration.

### `FOREIGN`

`FOREIGN` không có target representation trong V4.1.

V4.1 không định nghĩa mapping:

```text
FOREIGN → Province/District-level unit
```

Nếu legacy persisted `FOREIGN` tồn tại tại thời điểm migration, record đó không thể được coi là migrated hợp lệ chỉ bằng automatic geographic mapping.

Nó phải được phát hiện và xử lý trước khi Data Completion được xác nhận.

Không tự tạo:

```text
provinceCode = FOREIGN
```

hoặc synthetic Province để giữ compatibility.

---

## 8.10. Legacy Candidate preferred Locations migration

### Trước

```text
preferredLocations = [
  LEGACY_PROVINCE_A,
  LEGACY_PROVINCE_B
]
```

### Sau

```text
preferredLocations = [
  {
    provinceCode: mappedProvinceA,
    districtCode: null
  },
  {
    provinceCode: mappedProvinceB,
    districtCode: null
  }
]
```

Legacy province preference được migrate thành Province-wide preference.

Không tự tạo District-level unit preference từ legacy data.

Sau mapping phải loại duplicate canonical selections nếu nhiều legacy values hợp lệ cùng quy về một canonical Province.

# 9. Transaction / Atomicity Requirements

V4.1 không bổ sung cross-document business invariant mới yêu cầu database transaction giữa nhiều business entities.

Các Location transition thông thường thay đổi một document:

```text
Job
```

hoặc:

```text
CandidateCV
```

và phải tận dụng atomicity của một persisted document.

## Job Location atomicity

Một Location update phải persist như một coherent unit.

Không được commit:

```text
new province
+
old incompatible district-level unit
```

như một valid persisted state.

## Candidate preference atomicity

Một update preference phải hoàn tất với một valid `preferredLocations` array.

Không được persist final state có:

```text
Province / ALL
+
District-level unit subset cùng Province
```

do partial update.

## Migration

V4.1 không yêu cầu toàn bộ `jobs` và `candidate_cvs` phải được migrate trong một database transaction duy nhất.

Mỗi document migration phải atomic đối với document đó.

Migration completion phải được verify trước khi legacy Location representation được coi là loại bỏ hoàn toàn.

Không suy diễn requirement này thành:

- distributed transaction với external Location provider;
- exactly-once guarantee với external provider;
- atomic commit giữa database và external HTTP request.

External Location source không sở hữu persisted transaction state của JOBHUB trong V4.1.

# 10. Constraint Ownership

## 10.1. Database / schema bảo vệ

Database/schema chịu trách nhiệm đối với local structural invariants mà một document có đủ context để xác định.

| Constraint | Owner | Lý do |
|---|---|---|
| Job Location là `null` hoặc đúng structured shape | Schema | Local structure |
| `provinceCode` required khi Location tồn tại | Schema | Local invariant |
| `districtCode` nullable | Schema | Local structure |
| District-level unit-only representation bị cấm | Schema | Có thể xác định trong document |
| Candidate preferred item phải có `provinceCode` | Schema | Local structure |
| Candidate preferred `districtCode` nullable | Schema | Local structure |
| Exact duplicate preferred selection bị cấm | Schema / document validation | Local array invariant |
| Province-wide và District-level unit subset cùng Province không được coexist | Schema / document validation | Local CandidateCV invariant |
| `FOREIGN` không phải canonical V4.1 persisted Location | Schema / document validation | Local forbidden legacy representation |

Database/schema **không được tự xác định** rằng code tồn tại trong external authoritative catalog nếu database không sở hữu catalog đó.

## 10.2. Service / semantic validation bảo vệ

| Constraint | Owner | Lý do |
|---|---|---|
| `provinceCode` tồn tại trong canonical Location source | Semantic Location boundary | Cần external reference context |
| `districtCode` tồn tại | Semantic Location boundary | Cần external reference context |
| District-level unit thuộc Province | Semantic Location boundary | Cross-reference với external catalog |
| Actor có quyền chỉnh Job | Existing Job business layer | Authorization rule |
| Job lifecycle cho phép thay Location | Existing Job business layer | Business transition |
| Candidate có quyền chỉnh CV | Existing CandidateCV business layer | Ownership |
| Job completed state phải có Location | Existing Job business rule + V4.1 Location validity | Lifecycle context |
| Job Discovery hierarchy matching | Job Discovery business layer | Search semantics |
| Candidate Search willingness matching | Candidate Search business layer | Search semantics |

Không ép persistence schema tự thực hiện external Location lookup.

External semantic validation thuộc catalog và Job/CandidateCV mutation path
cần xác minh code trước khi persist. Sau khi code đã persist, Job Discovery và
Candidate Search áp dụng hierarchy predicates trực tiếp trên
`provinceCode`/`districtCode`; filter/sort query path không revalidate từng
persisted record.

Riêng Candidate Search: khi filter có District-level unit subset, District →
Province membership của filter input được xác nhận một lần mỗi request qua
semantic Location boundary trước khi build predicate, vì Province-wide
preference (`districtCode = null`) không mang District để chứng minh membership.
District không tồn tại hoặc không thuộc Province đi kèm chỉ không match.
Province / ALL filter và Job Discovery không cần lookup này, vì persisted
`(provinceCode, districtCode)` đã được validate khi persist.

# 15. Compatibility với version trước

## 15.1. Invariant phải giữ

V4.1 phải giữ:

- một Job có đúng một Location khi lifecycle yêu cầu;
- Job DRAFT có thể chưa hoàn thiện Location nếu existing Job contract cho phép;
- Candidate có thể có nhiều preferred Locations;
- Candidate CV ownership không đổi;
- Job ownership không đổi;
- WorkMode không đổi;
- `REMOTE` vẫn không phải Location;
- OR trong Location group được giữ;
- non-Location filter semantics không đổi.

## 15.2. Persistence behavior phải giữ

Các field không liên quan Location trên:

```text
jobs
candidate_cvs
applications
job_invitations
```

không bị reinterpret chỉ vì V4.1.

`CandidateCV.generatedContent.personalInfo.displayLocation` tiếp tục là independent free-text field và không được migrate sang structured Location.

## 15.3. Thay đổi được phép

V4.1 được phép:

- thay scalar `Job.location` bằng structured Location representation;
- thay scalar-array `CandidateCV.preferredLocations` bằng structured selection array;
- loại bỏ legacy Location enum constraint;
- loại bỏ `FOREIGN`;
- thay Location indexes;
- migrate legacy Province literals thành Province-only structured Location;
- thay persistence predicates cần thiết để đáp ứng hierarchy semantics đã được Product chốt.

## 15.4. Thay đổi không được phép

Không được:

- biến một Job thành multi-location Job;
- bắt buộc District-level unit khi Product cho phép Province-only;
- tự tạo District-level unit ngoài canonical Province Open API v1 catalog;
- giữ `FOREIGN` dưới một synthetic internal Province;
- biến `REMOTE` thành Location;
- migrate `displayLocation`;
- thêm historical Location semantics;
- thay non-Location business state;
- thay tenant ownership;
- thay authorization chỉ vì representation Location thay đổi.

# 16. Persistence Invariants

Các invariant sau phải luôn đúng ở persisted state sau khi V4.1 migration hoàn tất:

1. Canonical Job Location không còn là legacy string literal.
2. Canonical Candidate preferred Location không còn là legacy string literal.
3. `FOREIGN` không tồn tại như canonical persisted Location.
4. Mọi non-null Job Location có `provinceCode`.
5. Job `districtCode` có thể `null`.
6. Nếu Job có `districtCode`, District-level unit phải thuộc persisted `provinceCode`.
7. Job không persist nhiều Location.
8. Province-only Job là valid persisted state.
9. District-level unit-only Job không phải valid persisted state.
10. Mọi Candidate preferred selection có `provinceCode`.
11. Candidate preferred `districtCode` có thể `null`.
12. `(provinceCode, null)` biểu diễn Province-wide Candidate preference.
13. `(provinceCode, districtCode)` biểu diễn exact District-level unit preference.
14. CandidateCV không có duplicate preferred selection.
15. CandidateCV không được đồng thời có Province-wide và District-level unit-specific preference cho cùng Province.
16. Mọi persisted District-level unit preference phải thuộc Province tương ứng.
17. Empty Candidate preferred Locations vẫn được hiểu theo existing CandidateCV optionality contract.
18. Location code không xác định tenant ownership.
19. Province/District-level unit catalog không thuộc riêng Company nào.
20. Application và Invitation không tạo duplicate canonical Location state nếu existing ownership không yêu cầu.
21. `displayLocation` không bị reinterpret thành canonical structured Location.
22. Không persist `ALL` như một fake District-level unit.
23. Không persist `REMOTE` như Location.
24. External Location raw representation không trở thành canonical business persistence.
25. Không có `Location`, `Province` hoặc `District-level unit` Mongo collection chỉ để mirror provider trong V4.1.

### Enforcement ownership

| Invariant group | Enforcement owner |
|---|---|
| Embedded shape / required fields | Schema |
| Candidate local duplicate/exclusivity | Schema/document validation |
| Province/District-level unit existence | Semantic Location validation |
| District-level unit → Province relationship | Semantic Location validation |
| Job lifecycle completeness | Existing Job business layer |
| Ownership/authorization | Existing owning service/domain |
| Migration completeness | Versioned migration verification |

# 17. Definition of Data Completion

Data Contract V4.1 được coi là đáp ứng khi:

- `Job.location` canonical representation đã được xác định;
- `CandidateCV.preferredLocations` canonical representation đã được xác định;
- Province-only và Province + District-level unit persistence semantics rõ ràng;
- District-level unit-only invalidity được enforce;
- Candidate Province-wide và District-level unit-subset persistence semantics rõ ràng;
- duplicate/exclusivity rules của Candidate preferences rõ ràng;
- Province/District-level unit semantic references có owner rõ ràng;
- Location-related indexes cho Job Discovery được xác định;
- Location-related index cho Candidate Search được xác định;
- legacy scalar Location migration được xác định;
- legacy Candidate preferred Location migration được xác định;
- `FOREIGN` không có target canonical persistence;
- không tự suy ra District-level unit từ legacy Province;
- persistence transitions đã được xác định;
- không có cross-document transaction requirement bị tạo ngoài business need;
- constraint ownership giữa schema/database và semantic validation rõ ràng;
- multi-tenant data boundary được giữ;
- không có historical snapshot requirement ngoài Product Contract;
- compatibility với các version trước được giữ ngoài các Location rule bị V4.1 supersede;
- mọi persistence invariant có enforcement owner;
- không có speculative Location collection/field ngoài requirement;
- Explicitly Excluded Persistence không bị implementation ngoài ý muốn.

Data Completion không đồng nghĩa với việc schema hoặc migration đã được code.

Nó có nghĩa persistence contract đã đủ rõ để implementation không phải tự quyết định lại business hoặc data architecture cốt lõi của Location V4.1.
